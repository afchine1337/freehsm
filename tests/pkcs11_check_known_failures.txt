# pkcs11-check failures that are known and accounted for, per build profile.
# Read by scripts/pkcs11_check_gate.py; any failure NOT listed here fails the
# signed-module job in .github/workflows/pkcs11-check.yml.
#
# Format: <profile> <node-id>, one per line. <profile> is nist-approved-only,
# all-mechanisms, or * for both. The node-id is normalised the way
# scripts/diff_pkcs11_runs.py normalises it -- from `pkcs11_check/` on -- so it
# does not depend on where the harness is installed.
#
# An entry is a claim that someone read the failure and decided it is not the
# module's to fix. Each carries its reason. Adding a line to make CI green
# without one is how a finding stops being read.
#
# Measured on 2026-10-06 in both profiles, pkcs11-check 0.2.3, full corpus,
# signed module (reports/pkcs11-check-nist-0.2.3, reports/pkcs11-check-all-0.2.3).
# Moved to 0.3.0 on 2026-11-21, after runs by hand with an unsigned module
# (reports/pkcs11-check-nist-0.3.0b, reports/pkcs11-check-all-0.3.0).
#
# The three 0.2.3 entries -- the PKCS#1 v1.5 structured oracle and the two
# C_AsyncGetID probes -- were removed on 2026-11-22. In the full-corpus runs
# of 0.3.0 the oracle test is an xfail (implicit rejection recognised) and
# the async probes are skipped on CKR_FUNCTION_NOT_SUPPORTED, in both
# profiles (reports/pkcs11-check-nist-0.3.0b, reports/pkcs11-check-all-0.3.0b).
# CI could not have confirmed it: none of the three is in the embedded
# corpus it runs on push.
# ===========================================================================

# 0.3.0: the CKM_AES_CTS variant detection imports its probe key with
# C_CreateObject in a session that is not logged in. The module answers
# CKR_USER_NOT_LOGGED_IN, the detection fails, and the 7,499 CTS vectors are
# skipped. The harness's to change: mingulov/pkcs11-check#89.
*  pkcs11_check/testcases/acvp/aes/test_cts.py::test_cts_variant_detected

# 0.3.0: encrypts twice with the same all-zero counter block, only
# ulCounterBits differing (32, then 64), and expects two ciphertexts. Over
# two blocks the counter never wraps, so any correct CTR gives one.
# mingulov/pkcs11-check#92. Camellia runs only where a provider other than
# the FIPS one serves it, so this fails in the unsigned job, not the gated one.
all-mechanisms  pkcs11_check/testcases/test_camellia.py::TestCamelliaCTR::test_camellia_ctr_different_nonces

# 0.3.0, signed jobs only: imports an X25519 private key without asking
# whether the module serves Montgomery curves. The FIPS provider has no
# X25519, so the module lists no Montgomery mechanism and answers
# CKR_CURVE_NOT_SUPPORTED, which the test does not count as a refusal. The
# unsigned runs, where the default provider serves X25519, pass it.
# Upstream: mingulov/pkcs11-check#93.
*  pkcs11_check/testcases/test_object.py::TestAttributeValueEncodings::test_private_ec_family_value_raw_known_material[montgomery]

# 0.3.0: the X9.31 oracle opens the signature as s^e mod n and checks the
# block. X9.31 signs min(s, n - s), as OpenSSL's RSA_X931_PADDING does, and a
# verifier takes n minus the result when its last nibble is not 0xC; the
# oracle does not, so it refuses every signature where s > n/2, about half
# of them. The module's own verification and tests/test_rsa_x931.c accept
# both. Each test fails or passes by chance, so the gate's "did not fail"
# notice for these two means nothing. Upstream: issue to be filed. X9.31 is
# offered only where a provider other than the FIPS one serves RSA, so in
# the unsigned job.
all-mechanisms  pkcs11_check/testcases/test_rsa_extended.py::TestRSAX931::test_sign_verify_sha1
all-mechanisms  pkcs11_check/testcases/test_rsa_extended.py::TestRSAX931::test_sign_verify_sha256
